# Security Policy

## Reporting a vulnerability

Report suspected security vulnerabilities privately to **irvanadwifangga@gmail.com**, with the subject `Security report: yt-to-mp3`. Do not disclose vulnerability details in public issues or pull requests.

Include, where available:

- The app version, operating system, and architecture.
- The affected component and any relevant yt-dlp or FFmpeg version.
- Steps to reproduce, a minimal proof of concept, and the expected security impact.
- Any workarounds you have identified and a safe way to contact you.

Remove credentials, session tokens, personal information, and private media from evidence. Use a synthetic example where possible. If a report requires sensitive attachments, ask the maintainer how to share them before sending them.

The maintainer will review the report and coordinate any clarification, remediation, and disclosure with the reporter. Please allow time to investigate before publishing details. This is a community-maintained project; response and fix timelines depend on maintainer availability.

## Versions and dependencies

When possible, check whether the problem affects the [latest release](https://github.com/irfanadwifangga/yt-to-mp3/releases/latest). If you cannot reproduce it there, include the affected version and the difference you observed. Do not assume older releases receive security backports.

For vulnerabilities in yt-dlp, FFmpeg, or another dependency, report them through the upstream project's security channel as appropriate. Also notify this project privately if its integration or distributed configuration is affected.

For ordinary bugs and usage questions, see [SUPPORT.md](SUPPORT.md). For harassment or other conduct violations, use the reporting process in the [Code of Conduct](CODE_OF_CONDUCT.md).
